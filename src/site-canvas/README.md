# Site canvas

The canvas beside Home, Pages and Design. It opens with the page on view, in Browse, and **Edit** at the right of its toolbar. Edit opens the page to change and fills the editor, hiding the sidebar and the screen beside it, and gives way to **Exit** and **Save**. Editing is a session of its own (`src/edit-session.js`): Save, and its review, save only what changed since Edit, and stay in Edit. Exit leaves without saving: what changed since Edit is discarded, the page is on view again and the sidebar comes back. Anything unsaved before Edit, like a colour picked on Colors, is left alone by both, and waits, with every other change made outside editing, for Publish, at the foot of each screen beside the canvas (`src/top-bar/publish.jsx`). Every way into editing fills the editor, screens that open a page to change included, except the canvas switching to show a change made beside it, as on Colors, which leaves the canvas where it is so as not to hide what the change was made with. Save shows only while editing. Document Overview's toggle, labelled **Document info**, leads the toolbar while editing, above the editor's sidebar at the canvas's left where it opens **Details** and **Layers**, then undo and redo; Exit closes them. For a page built from sections, Layers lists the page as the canvas works on it (see "Document Overview" below); anything else keeps core's list of blocks. On the right, as in core's editor, the View menu picks the device the page is shown on, Desktop, Tablet or Mobile, its button showing the device's icon, and ends with **Open in a new tab** for the live page and **Open in advanced editor** for the full-screen editor, and while editing, Zoom out beside it steps back to work on the page's sections.

- **Browse**, the default, and where Exit returns to. The site in an iframe, as visitors will see it once the unsaved changes are saved: nothing is laid over it, and links can be followed to other pages. Edit is the way to change it.
- **Edit**, from the Edit button. The page in core's editor, with our own layer over it. A section is worked on a click at a time: the first click picks it, a click on a row of cards opens the row, and the next reaches the words or picture clicked. See "Edit's section layer" below. A section's blocks aren't locked: once reached, each is changed, moved, added to and removed with core's own tools. A layout, like Single Post, is edited block by block unless the site says it is built from sections. "Open in advanced editor", at the end of the View menu, opens the full-screen editor for anything the canvas doesn't suit. A page that isn't a post or page of its own, like an archive or the search results, is changed by changing the layout it is made with: the site says which when asked with `_wp-find-template` (`src/records.js`), and Edit opens that layout, in purple, as it changes every page made with it.
- **Compose**. The same editor zoomed out, with the same section layer as Edit over it. Sections are dragged to reorder the page, a ghost of the section following the pointer, and a section's layout, colours and place on the page (move, duplicate, delete, add a section) change without leaving. Its bar has no Add. Instead, **Edit content**, beside Edit design, zooms back into Edit with the section picked and brought into view, ready to click into. Anything else, like a double click to reach a section's words, zooms back into Edit and does it there. It is editing from further away, so Exit stays. Zoom out, pressed again, the + in the canvas's corner, or Escape with nothing picked, returns to Edit. Compose lays the page out as on a desktop, so the View menu shows Desktop while it is on, and picking a device zooms back in.

Only what the site says is built from sections, like a page, has them: `src/sections.js` asks, and `docs/architecture.md` says how the site decides. Everything else, a post, a layout (what WordPress calls a template) wherever it is reached, a product, WooCommerce's cart and checkout, is edited block by block with core's own tools: no sections, no Add section, no Compose, and core's inserter between blocks. Its template parts still get the same treatment as on a page (see below), and every other click reaches the blocks. A page's runs of plain blocks are grouped into one "Text" section each (`writing-mode.js`), never in the saved content.

Whatever has sections groups its runs of plain blocks, so a page that is mostly words, like a privacy policy, is one "Text" section rather than a section for every paragraph. The first click picks it and the next reaches the words, as for any section. It has Add and its moves, but no Edit design.

The mode is shared by every canvas, so it carries over from page to page and screen to screen. It lives in a small data store (`mode.js`), because app init and each route are built separately. Nothing is saved, so every visit starts in Edit, not expanded. Whether the canvas is expanded is kept in the same store; leaving a screen's canvas puts it back.

The preview shows unsaved changes too. Before it loads, the canvas sends the editor's unsaved changes to the site, kept for this editor alone, and the preview shows the site as it would be once saved (`preview-changes.js`, and `docs/architecture.md`). So Browse anywhere, after changing the site's name or colours on another screen say, shows them. Moving to Browse with changes the preview can't show, like a page's order, asks to save or discard them. Moving between Edit and Compose never asks: they are the same editor.

A change made from the sidebar while browsing still brings the editor up to show it, as the editor shows it at once, where the preview would have to load again.

## Pointing at Edit

Browse and Edit show the same page, so people click words or pictures in Browse expecting to change them. `useEditHint()` listens to the preview for those clicks and points at Edit.

- The first time, it asks for the Edit onboarding tip (`src/onboarding/`), which darkens the rest of the editor round Edit with a popover beside it saying that's where changes are made. Like every tip, it's shown once per person, never to someone who has already clicked Edit, not after "Don't show hints like these", and not in a workspace with onboarding off, such as Builder.
- Whenever the tip won't show, the click pulses Edit instead. That answers the click rather than teaching, so it happens in every workspace and with hints turned off. With reduced motion it is a still ring for a moment instead.
- A double click on words or a picture goes straight into Edit, as Edit does. A single click waits a moment before pointing at Edit, so the spotlight doesn't come up between the two clicks of a double click.
- It keeps out of the way while a menu, popover, dialog or the page finder is open, judged as the press starts, since clicking the preview closes a popover before the click arrives.
- For screen readers, the tip is a dialog named and described by its words, and takes focus. The pulse can't be seen, so the first one on each page also says "To change this page, use the Edit button." politely.
- Only a click on a line of words (`caretPositionFromPoint`, so the space round words doesn't count) or a picture counts. A click in a link, button, form, menu, toggle or anything else that works on the site never does, so the site can be used as visitors use it.

## Document Overview

Document Overview is core's list view sidebar, taken over by `document-panel/`. Its toggle carries a label as well as an icon, "Details", since a list icon alone didn't say it was about the page. Core's List View and Outline tabs give way to two of ours:

- **Details**, picked first, says what the document is: its type, title and length, which Outline used to give, then for a page every detail the Pages screen has. Its Layout leads to Change layout in place, with Back. Other kinds of document only get their name and length so far.
- **Layers** is core's List View, renamed.

Both tabs' icons are the canvas's own (`icons.jsx`), as `@wordpress/icons` has nothing for page details or layers. The tab picked is kept while the sidebar is closed.

For a page built from sections, Layers lists the page as the canvas works on it rather than block by block: a row each for the sections, a run of text being one "Text" row, under **Header**, **Content** and **Footer** headings, as the canvas names them. Header is the header parts at the top of the page and Footer the footer parts at its bottom. Everything between is Content, in page order: the sections, any other template part, like a sidebar, and the blocks the page's layout places, like its title and featured image. Those, and the parts, have the purple icon the canvas marks site-wide things with, and a layout's own blocks a lock, named "Part of the layout".

The rows wear core's list view classes, so core's styles draw them: the same height, chevrons, indents and filled row for what is picked, so the list reads as core's does to anyone who has used it. A section with blocks opens, by its chevron or Right and Left, to the blocks inside it, from core's own list view tree (`getListViewClientIdsTree`), so it lists what core's list would. A run of text opens to its paragraphs. Rows start closed, and a block selected on the canvas opens the rows down to it, as in core. The header and footer only open once Edit header or Edit footer has opened them, as their blocks can't be reached until then, and they open in the list as they do. Each has an edit button at the end of its row, where core's list view has its options, that opens it as Edit header or Edit footer does. It always shows, as it is the way into the part, and goes while the part is open. Locked, the row has no chevron, nor room for one, so its icon lines up with the heading above.

A click on a section's row picks it on the canvas, as a click there does, and brings it into view. A click on a block's row goes into its section, as a double click on the block does, and selects the block, leaving the focus in the list. The row picked is the block selected, or the section when nothing in it is. **Add section**, after the content, adds at the end of the page in place, as the canvas's own Add does. Header and footer have no Add section: they are changed with Edit header and Edit footer.

The tab is core's, so the list is portalled into its panel, and core's list view, still mounted there, is hidden. Outline is core's own. A canvas about one part, like the Header screen's, and anything not built from sections, keep core's list. See `docs/editor-workarounds.md`.

## Edit's section layer

Pointing at a section in Edit outlines it, names it in a tab and tints it. Its tools are on core's own block toolbar, the one every block has, which shows once it is picked (see "The section's toolbar" below). A run of text, which has no block of its own, a header or footer, and every section in Compose, where core's toolbar is hidden, keep a bar laid over them instead. The header and footer are named "shown on every page", and stay where they are.

A section is worked on a level at a time, a click at a time:

1. **The section.** A click anywhere on it picks it: outlined, untinted, and its block selected in core, so core's toolbar shows for it and names it in place of the tab.
2. **A row of cards**, if the click lands in one. Once the section is picked, a row pointed at is outlined with a "Cards" tag, and a click opens it, with its tools (see "Rows of cards" below). A click on anything not in a row skips this level.
3. **A block.** The next click reaches what it lands on: the caret where it landed in text, or a picture selected, with core's own tools, Replace for a picture among them, and Remove, added to the end of core's toolbar. Nothing in a section is locked, so every block in it has core's full toolbar, with its moves, options and "/", "+" and Enter to add more. The toolbar's parent selector leads back out, a block at a time, to the section and its toolbar.

Escape steps back a level at a time: from the block to the row, to the section, then un-picks it. A double click goes straight to the block, with the caret where it landed. A click on another section picks it instead. Internally, a section whose blocks are reached is in "Edit content", though nothing on screen names it, and there is nothing to leave.

Template parts show on every page that uses them, so their words aren't reached by clicking. Every template part counts, wherever it is and whatever is being edited, a page, a post or a layout: the header and footer, and a sidebar or a second header just the same, as `useComposeStructure()` finds them by being template parts, not by their names. **Edit header**, **Edit footer** or **Edit** and the part's name, like **Edit sidebar**, alone on its bar, opens one with core's own unlock. Until then it is locked, and darkened only while pointed at, as any section is, the same on any page as on the Header and Footer screens. Open, only its content can be selected and changed, its words, pictures, links and buttons, as core's own content-only lock opens a pattern: the groups, rows and columns that lay it out are disabled. So is a Page List, so a click on a menu listing the pages picks its Navigation block, the menu. Edit design's bar opens with it, under it so it never covers what is being changed, with Done editing at the end of its choices in place of Back, which locks it again. A choice drilled into, like Colour, has Back only. A design choice lets go of any block selected in it, and Escape steps back from a choice to the choices first.

A header or footer in a mode, Edit design, Edit header or footer, or Freeform, is put in the spotlight, the rest of the page faded and dimmed behind a dark backdrop, as on the Header and Footer screens (`part-spotlight.js`), so it looks the same however it is reached.

A canvas about one part of the site, like the Header and Footer screens', passes it as `focusId`. The layer then offers only that part, picked from the start so its bar shows straight away, and the rest of the page can't be pointed at or clicked.

`SiteCanvas` gives the layer `hasSections` only while it edits something built from sections, and nothing else decides: a screen doesn't turn sections on or off itself. Without sections, the layer only opens the template parts: a click anywhere else reaches the blocks, as core's own editor has them, and leaves any part open or picked.

A canvas can give core's editor settings of its own for what it edits as `editorSettings`, as a layout's does to open up the blocks patterns add, which core otherwise keeps content-only. Core's editor settings are shared by every editor, so `use-own-editor-settings.js` hands the editor's own values back when the canvas goes.

### The section's toolbar

A section picked in Edit has core's block toolbar, filled as any block's is by `src/block-toolbar/`, with the section's own tools from `section-controls.jsx` there in place of a container's Layout menu. It is laid over the top of the section, where the section's bar used to be, rather than above it: stuck to the section's top, as far in from it as from the side, or to the canvas's top while the section's is scrolled out of view, and under a section too short to hold it (`use-section-toolbar-place.js`). Its own tools each have an icon and a name:

- **Section**, beside its icon, or the name it has been given, rather than its block's, Group. A section isn't turned into another block, so pressing the name opens **Layers** in place of core's menu: only the blocks inside the section, in core's List View rooted at it, in a popover under the name. Picking one goes into the section with that block selected. A section that holds no blocks has a label for a name. It has no parent selector, being the outermost thing to pick.
- Its **moves**, as on any block.
- **Add**, core's quick inserter, which adds any block as the section's last.
- **Layout**, **Colour** and **Width**, each shown only when the section has something to choose. Each opens its options in a popover under the toolbar, hung from its button, which the button, Escape or a click elsewhere closes; the toolbar stays. Layouts are a grid of every one at once, up to four to a row and never one left on its own. Each is drawn with the section's own content, in cards larger than the other pickers' so the arrangements can be told apart. Pointing at a layout, or moving to it with the keyboard, shows it in the section's place on the canvas as a passing change, which isn't saved or undone, and the section comes back once nothing is pointed at or the popover closes. Clicking one puts it in for good, without moving focus, so the canvas doesn't scroll, and the popover stays open on it where it opened. The layouts offered stay as they were while picks are made, rather than being worked out again from the new shape, so the cards don't move under the pointer, and the layout the section had when they opened is tagged Original, as the way back to it. See [editor workarounds](../../docs/editor-workarounds.md). Colours are a list, as a menu's choices are: each choice's background, text and accent in core's overlapping colour circles, as its block Color panel draws them, then its name, with a tick on the one in use. It is one tab stop: the menu opens on the colour in use, arrow keys move through the rest, Enter picks, and Escape returns to the Colour button. The theme's own comes first, as **Default**, in the page's colours. Colours set on a block win over a picked one and are never taken away behind anyone's back, so a section with colours set on its own block is offered none (colours that only repeat the page's own count as Default), and a section with text colours set inside is offered only the colours that text can still be read on. The last, after a divider, is **Custom colours**, with a colour wheel, or the section's own colours once it has them. It picks nothing by itself: it drills into a screen of its own in the same popover, as Global Styles moves between screens (core's `Navigator`), with Back and the section's own **Background**, **Text** and **Button** colours as rows, as core's block Color panel lists colours, each opening core's colour palette beside it. The arrow pointing forward drills in; Back, the arrow pointing back or Escape returns to the list on Custom colours. Edit design's bar keeps its tray under the colours instead. Headings and links take the text colour, and button words whichever of the section's colours reads on the button, or the palette's best when neither does. They are saved on the section's own block with core's colour settings, palette colours by preset. Whatever is picked goes in at once, and undo takes it back.
- **Options** and **Delete**, at the end, as on any block: the options menu has the section block's own settings, under "Section", Duplicate among them.

The canvas and the toolbar are built separately, so they talk through the canvas's store (`mode.js`): `section-tools.jsx` says which choices the section picked has, the toolbar's buttons, and its name for Layers, say which tool is open with `toggleSectionTool()`, and `section-tool-popover.jsx` draws it. `use-section-toolbar.js` keeps core's selection on the section picked, and closes the tool once another section, or a block, is. There is no More control and no Freeform for a section: its blocks are open as they are, with `disableContentOnlyForUnsyncedPatterns` set for the editor so core doesn't lock the ones patterns add.

A header or footer still has Edit design's bar while it is open, listing **Layout**, **Colour**, **Width** and **More control**, each drilled into in the same bar with Back leading out again; so does a section in Compose, without More control. More control is Freeform: core's own unlock for the header or footer, for core's full block tools, left with Done editing, Escape or a click elsewhere.

While core has a header or footer open, it fades the rest of the page. It expects the part selected, and fades that too until something in it is, but the layer never selects it, so the layer keeps it clear itself.

The rest of what the layer offers:

- **Add**, on a run of text's bar: a heading, paragraph, button or image, put in place of the empty line the caret is on, or else last in the run. An image is chosen from the media library first.
- **Rows of cards**: a row of columns or a grid of two or more items made of the same kinds of blocks, like three cards each with a picture, a heading and words, is the second level in. Once open, it stays open while its cards' words are worked on. While it is open, where its last line has a gap beside its cards, as when four sit in a row and there are five, a dashed placeholder card with "Add card" fills it. Where there's no gap, a slim strip with a + on the right of the last card adds one beside it: one more side by side, for a row on one line, the columns or the grid growing, or a card wrapping onto a new line for a grid of more. Either adds a copy of the last card, words and picture too, so it looks finished and is typed over. The card under the pointer has a remove button on its corner. "Per row 2 3 4", under the row's end, sets how many sit side by side, the rest flowing onto the next line; a row of columns becomes a grid to do so, as Layout's per row does. A row holds two to six columns, or twelve cards in a grid, six at most side by side. Not on a header or footer.
- **Manage posts**, alone on a bar over a section with a query loop in it (after Edit design in Compose), named after what the loop lists, like **Manage products**. It opens a small menu of labelled dropdowns, nothing else of the query loop's: **How many to show** (whole rows of the theme's grid, 3, 6 or 9 for three across, so the last row is never half empty, or 3, 5 or 10 for a list), **Show posts from** a category, offered when the post type has more than one (a shop's product categories for its products), and **Order**, newest or oldest first. Changes go in at once. A loop that lists what the page would, as an archive's does, follows WordPress's query, so its menu has none of them. Under them, **Manage all posts** leads to the posts' screen in the editor, as they aren't written on the page. The first time, a notice says what posts are (the news, stories and updates published over time, like a blog's entries), that they show up in the section by themselves, and that the page's changes are kept; going on means it was read, and it isn't shown again (a preference), while **Stay here** leaves it for next time. The way back is kept in the canvas's store (`setPostsTrip()` in `mode.js`): the posts' screen starts its breadcrumbs with the page's name, and coming back opens the page with the section picked again and scrolled to once its pictures have loaded. Not on a header or footer.
- **Move up, move down, duplicate and delete**, at the end of a run of text's bar, and of every section's in Compose. Deleting offers Undo.
- **Add section**, on the section's top and bottom edges, opens that gap in place: the sections move apart, the gap is marked out edge to edge in grey, square as a section is, and a dashed placeholder in it offers the designs and the templates as two carousels, shuffled each time with the theme's own designs first, and scrolled with their arrows, a trackpad or a mouse wheel, then **Start blank**, with **View all sections** to open the section picker for the same gap. Core's inserter between blocks is hidden while it is open. A design or template is added and picked. Blank is typed into straight away: a full-width section with the theme's room above and below, its blocks free. The section picker's Start blank does the same. Escape, the close button or a click on the page closes the gap. The gap is a margin the layer adds to the canvas, so nothing goes into the page until something is picked. The section's options menu and the empty page still open the section picker.

A page with nothing in it shows a placeholder across the canvas instead: the design system's empty state in a dotted box, with **Add a section**, which opens the section picker, and **Start blank**, which adds a blank section, ready to type.

A section added from the section picker is picked and brought into view. Pointing at another section shows its bar, the picked one keeping its outline and name. A click off the sections un-picks it.

Only one section is worked on at a time. Leaving Edit design, Freeform or an open header or footer, with Done editing or Escape, leaves the section picked. From a design choice, Escape steps back to the choices first. The bars follow a tall section as it scrolls.

In Freeform a header or footer has a bar with Done editing, and Restore when something was removed. Its mode is named for assistive technology only. In a big section the bar is the size of the bar over a section pointed at, in the middle of whichever of its top and bottom edges is in view. A small section has a smaller bar outside it, under its bottom edge or over its top, so it never covers what is being edited.

Changes rewrite the blocks around an item with core's `replaceInnerBlocks`, so they are undone like any other edit. A double click in Compose zooms back into Edit with the block there selected.

## Compose

Core's zoom-out is used for its zoom alone. Core can't scale the canvas without also turning on the rest of its zoom-out mode, so the section layer keeps every click off the canvas, and the stylesheet hides core's zoom-out tools. The layer is the same one as Edit's, kept mounted between the two, so what is picked carries over. See "Edit's section layer" above.

| File | What it does |
| --- | --- |
| `use-compose-zoom.js` | Zooms the editor out and back in. Widens the editor to a desktop's width while core measures it, plus the Document Overview's when it is open, so the page is laid out as on a desktop and shrinks to fit. Once the zoom has settled, has core measure the canvas again, as core keeps the scale it worked out for the widened editor. Waits for core's zoom animation to end, for a scroll that would otherwise be lost. |
| `use-compose-structure.js` | The page's sections, the blocks of core's section root, and what the template adds around them, like the title, and which of those the page can change. And the template parts, every outermost one wherever it is, on anything edited. |
| `use-block-rects.js` | Where those blocks are on screen, measured every frame, and scrolling the canvas to one. |
| `section-styles.js` | The theme's section styles, as a section's colours. |
| `palette-colors.js` | Colour sets made from the theme's palette, for themes without section styles. |
| `section-colors.js` | The colours a section can take, from either, and putting one on. |

A section's layouts come from `src/layouts/variants/`: arrangements of the same content, worked out from the shape of the section's blocks, so they work for theme patterns as well as our layouts. After them come layouts made from the section's content, ported from [Ito](https://github.com/Automattic/site-editing-experiments/tree/trunk/ito) (`src/layouts/variants/from-content/`): Stacked, Centered, a picture moved, beside the text or behind it, Split in two, Card, a column more or fewer, and other grid shapes, leaving out any the arrangements already offer. So every section with content has a layout to choose; one that matches none of the arrangements has **As it is** first, as the one in use. Its colours are the theme's section styles, saved as core saves a block style. A theme without any gets sets made from its palette instead (soft, the page's colours swapped, and its strongest colours with readable text), saved with core's own colour settings by preset, so they follow the palette. A header's or footer's designs are the theme's patterns for its area, applied as core's Design panel does, and its colours are the same as a section's.
